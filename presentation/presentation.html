Introduction

Steer traffic with waypoints

  • 01Segment Routing sends packets along a segment path $\langle s, w_1, \dots, w_\ell, t\rangle$ through waypoints $w_k$.
  • 02Between waypoints, routing is classic shortest-path (ECMP).
  • 03The scheme is decided in advance over $T=\{0,1\}$ — nominal, then one maintenance period with links $q(1)$ down.
Speaker 1. SR lets us deviate from shortest paths by inserting waypoints — flexible and cheap to deploy. We plan the routing ahead of time for two periods: normal operation and a scheduled maintenance.
Objective

Minimize the most loaded link

$$\text{mlu}=\lambda_{\max}=\max_{a,t}\ \lambda(a,t)$$

Then flatten the whole load profile in decreasing order — the lexicographic min-max over all arcs and periods:

$$\text{lex}\min\ \big\{\lambda'(1),\ \lambda'(2),\ \dots,\ \lambda'(|L|)\big\}$$
Speaker 1. The measure is the maximum link utilization — the load of the busiest link. We minimize it, then lexicographically push down the second-busiest, third-busiest, and so on. $\lambda(a,t)$ is link load divided by capacity.
Step 01 · Theory

The network graph

  • 01Directed graph $G=(V,A)$, with vertices $V$ and arcs $A$.
  • 02Each arc carries a metric $\omega(a)$ (shortest-path weight) and a capacity $c(a)$.
  • 03One instance = three JSON files: net (topology), tm (demands), scenario (intervention + budget).
Speaker 1. The network is a weighted directed graph. Weights define shortest paths; capacities bound how much traffic an arc can carry. Node ids are remapped to Julia vertices 1…n.
Step 01 · Implementation

Graph.jl & the instance scale

  • 01Simple graphs only. Multigraph is out of scope.
  • 02Validation rejects duplicates and parallel arcs.
  • 03Down-link removal supports $t=1$.
Speaker 1 (≈2 min). We wrap Graphs.jl in a small module. Key scope decision: multigraph instances are not solved — SimpleDiGraph cannot hold parallel arcs. The challenge spans 20–400 nodes and up to 6000 demands.
Step 02 · Split coefficients

How flow is shared on shortest paths

$$r(i,j,a)=\dfrac{\sigma_{iu}\,\sigma_{vj}}{\sigma_{ij}}$$

ECMP splits flow evenly across equal-cost shortest paths. $r(i,j,a)$ is the fraction of $i\to j$ flow crossing arc $a$, from path counts $\sigma$ of one Dijkstra sweep per source — negligible runtime.

Speaker 1 (≈2 min). Link loads need split coefficients — the fraction of each node-pair's flow crossing each arc under ECMP. They factor as a ratio of equal-cost path counts. One counting Dijkstra per source gives distances and counts; this stage is essentially free.
Steps 03–05 · Theory

The MILP — variables & path

$$x^d_{ij}\in\{0,1\}\quad\text{segment }(i,j)\text{ used by demand }d$$

Flow conservation — one source→target chain per demand:

$$\sum_j x^d_{ij}-\sum_j x^d_{ji}= \begin{cases}+1 & i=s\\ -1 & i=t\\ 0 &\text{else}\end{cases}$$
Speaker 2 (≈2 min). Binary x: does demand d use segment (i,j)? Flow conservation forces exactly one source→target segment chain per demand.
Steps 03–05 · Theory

The MILP — load & objective

Segment cap (≤ maxSeg segments per path):

$$\sum_{i,j} x^d_{ij}\ \le\ \text{maxSeg}$$

Arc load — routed flow ≤ capacity × MLU:

$$\sum_{d}\sum_{i,j} r(i,j,a)\,\nu(d)\,x^d_{ij}\ \le\ \lambda\,c(a)$$
Speaker 2. The cap bounds the number of segments. The load constraint ties each arc's traffic to the objective λ — minimize λ and we minimize the MLU.
Steps 03–05 · Implementation

Model.jl — builder + HiGHS

  • 01A fluent builder (set_variables! → set_flowConservation! → set_segmentCap! → set_loadBounds!) assembles the model.
  • 02HiGHS solves it — 1% gap, 900 s limit.
  • 03Lexicographic min-max: freeze $\lambda$, then minimize the sum of the $k$ largest loads via a binary-free gadget.
Speaker 2 (≈1.5 min). The model is a JuMP-style fluent builder solved by HiGHS. For the lexicographic objective we use an OWA gadget — a continuous threshold plus slacks gives the sum of the k largest loads without extra binaries.
Steps 03–05 · Benchmarking

Parallel runs on the server

  • 01One process per instance (solve_instance.jl), results as JSON.
  • 02A RAM-aware work queue starts an instance only when memory and cores allow.
  • 03collect_results.jl folds everything into summary.csv.
Speaker 2 (≈1 min). We run the instances in parallel, gated by a RAM budget and a core cap so heavy instances never OOM the machine. Results are incremental.

Step 06 · Maintenance

The degraded graph

$$G_1=\big(V,\ A\setminus q(1)\big)$$
  • 01An intervention takes a set of links $q(1)$ down at $t=1$.
  • 02Split coefficients are recomputed on $G_1$ → $r_1$.
  • 03Node numbering is unchanged, so indices stay stable.
Speaker 3 (≈1.5 min). At t=1 a scheduled maintenance takes links down. We delete those arcs, keep the same node numbering, and recompute the split coefficients — that gives the second period's inputs.
Steps 07–08 · Budget & coupled model

Limit the rerouting

Budget — the number of waypoint changes is capped:

$$\text{dist}(P^0,P^1)=\sum_{d,i,j}\big|x^{d,1}_{ij}-x^{d,0}_{ij}\big|\ \le\ \kappa_1$$

One MILP over both periods, minimizing the MLU across all arcs in both periods.

Speaker 3 (≈1.5 min). Rerouting costs operations effort, so the challenge caps the number of segment changes with a budget κ. We linearize the absolute value and solve both periods together.

A tighter budget $\kappa_1$ allows less rerouting, so the $t=1$ load must degrade; a larger budget lets the solver re-route around the failed link.
