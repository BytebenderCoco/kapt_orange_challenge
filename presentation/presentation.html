The challenge

Keep the flow, even when a link goes down

  • 01An IP/MPLS backbone with a forecast traffic matrix.
  • 02Segment Routing: packets follow waypoints; between them, shortest-path ECMP.
  • 03Plan the routing in advance — nominal t=0, then a maintenance t=1 with links q(1) down.
  • 04Goal: keep the maximum link utilization (MLU) as low as possible.

Speaker 1.
Model · Decision variables

One binary per segment

$$x^{dt}_{ij}\in\{0,1\}\quad\text{segment }(i,j)\text{ used by }d\text{ at }t$$
# x^{d,t}_{ij}: 1 if demand d uses segment (i,j) at t @variable(model, x[d in demands, t in periods, i in 1:n, j in 1:n; i != j], Bin)

The routing scheme is fully determined by these ~|D|·|V|² binaries — the source of the scalability wall.

Speaker 2 (≈1 min).
Constraint (1) · Flow conservation

One path per demand

$$\sum_{j} x^{dt}_{ij}-\sum_{j} x^{dt}_{ji}= \begin{cases}+1 & i=s\\ -1 & i=t\\ 0 & \text{else}\end{cases}$$
for t in periods, demand in demands, i in 1:n rhs = (i == demand.source) ? 1 : ((i == demand.target) ? -1 : 0) @constraint(model, sum(x[demand,t,i,j] for j in 1:n if i != j) - sum(x[demand,t,j,i] for j in 1:n if i != j) == rhs)
Speaker 2 (≈1 min).
Constraint (2) · Segment cap

At most maxSeg segments

$$\sum_{i,j} x^{dt}_{ij}\ \le\ \text{maxSeg}$$
# hardware limit on packet-header labels for t in periods, demand in demands @constraint(model, sum(x[demand,t,i,j] for i in 1:n, j in 1:n if i != j) <= maxSeg)

Every instance uses max_segments = 6.

Speaker 2.
Constraint (3) · Load

Routed flow ≤ capacity × MLU

$$\sum_{d}\sum_{i,j} r(i,j,a,t)\,\nu(d,t)\,x^{dt}_{ij}\ \le\ \lambda\,c(a)$$
# load(a) = Σ r·φ·x on arc a = (u,v) load = @expression(model, sum( coeff * demand.volumes[t+1] * x[demand,t,i,j] for demand in demands for (i,j,coeff) in segments)) @constraint(model, load <= lambda * c)

Unreachable segments are fixed to 0, so a disconnected demand can't be routed at zero load.

Speaker 2 (≈1 min).
Constraint (4) · Budget

Cap the rerouting

$$\sum_{d}\sum_{i,j}\big|x^{dt}_{ij}-x^{d,t-1}_{ij}\big|\ \le\ \kappa(t)$$
# segmentChange ≥ |x^t - x^{t-1}| segmentChange = @variable(model, [d in demands, i in 1:n, j in 1:n; i != j], lower_bound = 0) @constraint(model, segmentChange[d,i,j] >= x[d,t,i,j] - x[d,t-1,i,j]) @constraint(model, segmentChange[d,i,j] >= x[d,t-1,i,j] - x[d,t,i,j]) @constraint(model, sum(segmentChange[demand,i,j] for demand in demands, i in 1:n, j in 1:n if i != j) <= beta)

The absolute value is linearized with a non-negative auxiliary — no new binaries.

Speaker 3 (≈1 min).
Objective (5) · Lexicographic min-max

Flatten the whole load profile

$$\text{lex}\min\ \big\{\lambda'(1),\ \lambda'(2),\ \dots\big\}$$
# S_k = sum of k largest utilizations (OWA) function add_lexLevel!(model, loads, caps, k) tk = @variable(model) d = @variable(model, [a in arcs], lower_bound = 0) for a in arcs @constraint(model, d[a] >= loads[a]/caps[a] - tk) end return @expression(model, k * tk + sum(d[a] for a in arcs)) end

Level 1 minimizes the MLU; each deeper level freezes the previous one and minimizes the next-largest load — binary-free.

What went wrong

The exact model hits a wall

  • 01Small instances solve optimally in 2.5 / 68 / 12 s.
  • 02From setA-04 (50 nodes, 200 demands) the solver hits the limit with no feasible point.
  • 03Root cause: ~|D|·|V|² binaries — up to 22.4M for setA-10.
Speaker 3 (≈1 min).
What went wrong

The overnight runs failed

  • 01t0: 10 instances launched at once (~31 HiGHS threads, no RAM gate) → only 2 of 10 finished; 8 failed.
  • 02t1: a solver process “Aborted (core dumped)” → the run died after 3 results.
  • 03Cause: the parallel launcher dropped RAM budgeting and started everything simultaneously.
