Introduction

Problem context & challenge goal

  • Segment Routing (SR): packets follow a segment path $\langle s, w_1,\dots,w_\ell, t\rangle$ through waypoints $w_k$; between consecutive waypoints, classic shortest-path / ECMP routing.
  • Routing is decided in advance over a time horizon $T = \{0,1\}$ — nominal ($t=0$) and one maintenance period ($t=1$) where a link set $q(1)$ is down.
  • Input: network $(G=(V,A), \omega, c)$, demands $D$ with volumes $\nu(d,t)$, intervention scenario $q$, reconfiguration budget $\kappa$, and maxSeg.
  • Output: one routing scheme $P^t$ per period that minimizes the maximum link utilization $\text{mlu}=\lambda_{\max}$, in decreasing lexicographic order of all link loads.

$$\text{lex}\min\ \big\{\lambda'(i) : 1\le i\le |L|\big\},\qquad \lambda'(i)=\text{$i$-th largest load over all arcs and periods.}$$

T-ASR · ROADEF 2026

Speaker 1 (≈1 min). SR lets us steer traffic over non-shortest paths by inserting waypoints — flexible, cheap to deploy. We minimize the worst-case link load (MLU), then flatten the whole sorted load profile (lexicographic min-max). Two periods only: nominal and one maintenance intervention.

Step 2 · Theory & implementation

Shortest paths & split coefficients ($r$)

Theory

Forwarding graph $FG(u,v)$ = arcs on any shortest $u\to v$ path.

ECMP: incoming flow is split evenly over the outgoing arcs of $FG(u,v)$.

$$r(i,j,a)=\frac{\sigma_{iu}\,\sigma_{vj}}{\sigma_{ij}}$$

Implementation

source/SplitCoefficients.jl

dijkstra_shortest_paths with allpaths=true — distances $d$ and path counts $\sigma$ from one sweep per source.

Results

Arc-on-shortest-path test: $d_{iu}+\omega(a)+d_{vj}=d_{ij}$.

Negligible runtime for the coefficient matrix — Dijkstra is not the bottleneck.

$\sigma_{ij}$ = number of equal-cost shortest $i\to j$ paths; $r(i,j,a)$ = fraction of $i\to j$ flow that crosses arc $a$.

T-ASR · ROADEF 2026

Speaker 1 (≈2 min). To compute link loads we need split coefficients: the fraction of each node-pair's flow that crosses each arc under ECMP. They factor as the ratio of path counts — one counting Dijkstra per source gives both distances and counts. This stage is essentially free; the MILP is the expensive part.

Steps 3–5 · Theory

Nominal model ($t=0$): MILP formulation

Decision variables — segment used or not:

$$x^d_{ij}\in\{0,1\},\quad i\neq j,\ \forall d\in D$$

Flow conservation — one $s\to t$ path per demand:

$$\sum_j x^d_{ij}-\sum_j x^d_{ji}= \begin{cases}+1 & i=s\\ -1 & i=t\\ 0 &\text{else}\end{cases}$$

Segment cap:

$$\sum_{i,j} x^d_{ij}\le \text{maxSeg}$$

Arc load — routed flow ≤ capacity × MLU:

$$\sum_{d}\sum_{i,j} r(i,j,a)\,\nu(d)\,x^d_{ij} \;\le\; \lambda\,c(a)$$

Objective — lexicographic min-max of the load vector:

$$\text{lex}\min\ \lambda'(1),\lambda'(2),\dots \quad\Longleftrightarrow\quad \min \lambda=\lambda_{\max}$$

T-ASR · ROADEF 2026

Speaker 2 (≈2 min). This is the core MILP. Binary x: does demand d use segment (i,j)? Flow conservation forces exactly one source→target segment chain; the cap bounds the number of segments; the load constraint ties each arc's traffic to the objective λ. We minimize λ (= MLU), and then lexicographically descend the sorted loads.

Steps 3–5 · Implementation

source/Model.jl — builder + lexicographic descent

  • Fluent builder AsrModelBuilder: seed the model, then set_variables!, set_flowConservation!, set_segmentCap!, set_loadBounds! → build → solve!.
  • Solver: HiGHS, 1% MIP gap, 900 s time limit.
  • Lexicographic min-max: after minimizing $\lambda=S_1$, freeze it and minimize $S_k$ = sum of the $k$ largest utilizations via a binary-free OWA gadget, with a warm start between levels.
  • Unreachable segments are fixed to 0 so disconnected demands cannot hide infeasibility.

$$S_k = k\,t_k + \sum_{a} d_a,\qquad d_a\ge \frac{\text{load}(a)}{c(a)}-t_k\ \ge 0$$

T-ASR · ROADEF 2026

Speaker 2 (≈1.5 min). The model is assembled with a JuMP-style fluent builder and solved with HiGHS. For the lexicographic objective we use the OWA / Ogryczak–Śliwiński gadget — a continuous threshold plus per-arc slacks gives the sum of the k largest loads without extra binaries, so the load profile gets flattened cheaply.

Fully headless and non-blocking: results are written per-instance as they finish, so a cancelled sweep keeps what completed.

Step 6 · Theory & implementation

Maintenance scenario ($t=1$) & degraded graph ($G_1$)

Theory

An intervention $q(1)$ takes a set of links down at $t=1$.

Degraded graph: $$G_1=(V,\ A\setminus q(1))$$

Split coefficients recomputed on $G_1$: $r_1(i,j,a)$.

Implementation

get_graph_by_downtimeLinks removes the down-links (node set unchanged, so vertex numbers stay stable).

Feeding $G_1$ back into SplitCoefficients gives $r_1$.

Results

Structural impact: removing links changes shortest paths, ECMP splits, and thus $r_1$ — some node pairs become unreachable (their segments are fixed to 0).

T-ASR · ROADEF 2026

Speaker 3 (≈1.5 min). At t=1 a scheduled maintenance takes one (or a few) links down. We build the degraded graph by deleting those arcs, keep the same node numbering, and recompute the split coefficients. That gives the second period's inputs for the coupled model.

Steps 7–8 · Theory & implementation

Reconfiguration budget ($\kappa_1$) & coupled model

Budget — limit waypoint changes between periods:

$$\text{dist}(P^0,P^1)=\sum_{d,i,j} \left|x^{d,1}_{ij}-x^{d,0}_{ij}\right|\;\le\;\kappa_1$$

Linearized with auxiliary segmentChange ≥ both signed differences.

Two-period model — one MILP over $t\in\{0,1\}$, minimizing the MLU across all arcs in both periods, subject to (1)–(4).

add_budgetBounds! links the periods in the builder.

T-ASR · ROADEF 2026

Speaker 3 (≈1.5 min). Rerouting has an operational cost, so the challenge caps the number of segment changes with a budget κ. We linearize the absolute value with a non-negative auxiliary variable, and solve both periods together so the MLU is minimized jointly rather than greedily period-by-period.

Conclusion

Summary & future work

What we have
  • Clean, modular Julia architecture (Graph, SplitCoefficients, Model, …).
  • Exact MILP with lexicographic MLU minimization (HiGHS).
  • Fully parallelized, RAM-aware benchmarking pipeline.
Limitations
  • Exact MILP hits TIME_LIMIT on large instances (binary explosion).
  • Multigraph instances out of scope.
Perspectives
  • Metaheuristics (greedy / local search / GRASP) for large networks.
  • Extend to the full horizon $T=\{0,\dots,h-1\}$.
  • Warm-start the MILP from heuristic waypoints.
